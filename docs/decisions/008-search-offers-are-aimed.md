# ADR-008: A search control's offer is aimed along the control's direction

## Status

Accepted

## Context

Turning a search control asked for an offer whose direction survived only as
a label: the offer was the undirected taste walk the Offer button runs, so
turning Grit up did not reliably make anything grittier (RFC-002).

## Decision

A search control's offer walks a target tilted along the control's own
direction in standardized φ, `π ∝ p_grammar · exp(β·(f + γ·s·ê·z))`, with γ
chosen by census, and its reply reports how far the offer actually moved that
way, which B's strip shows. The Offer button and Wander stay undirected.

## Options Considered

### Option 1: Filter undirected offers after the fact

Wastes renders; yields nothing when no walk heads that way.

### Option 2: More grafts

No transparent graft exists for Grit.

### Option 3: A tilted fitness (chosen)

Aims the walk itself, at no extra render cost (one memo per proposal).

## Consequences

### Positive

- Search controls do what their names say, and say so when they do not.

### Negative

- A new tuned constant (γ), which the reference must quote by name.
