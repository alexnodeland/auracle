# Test-quality audit: Rust tests of `auracle-session` and `auracle-wasm`

Scope: every `#[test]` in `crates/auracle-session` (117: lib.rs 74, perform.rs 13, guess/tests.rs 11, migrate.rs 6, own.rs 5, walk.rs 4, map.rs 3, farm.rs 1) and `crates/auracle-wasm` (97: lib.rs 53, live.rs 32, level.rs 5, explain.rs 3, shipped.rs 1, tests/shipped_wirings.rs 2, tests/boot_agrees.rs 1), at `main` 42bd322. Read-only. Nothing in the repo was edited.

**Timings.**
- Fast tier: CI run 37345520856 (`ci_sw_times.txt`).
- Slow tier: `dx/nextest_slow.log`, local, on a loaded machine. For a runner, the Makefile gives about 330 s for the search floor.
- Phase splits ("measured"): instrumented copies of single tests in a scratch copy of the workspace (`audit-copy`, `CARGO_TARGET_DIR=audit-target2`, `nice`, `--cargo-profile test-fast`). The machine's load average was 20 to 53 while they ran, so the absolute seconds are inflated. The proportions are what count.

**Severity policy.**
- A flimsy or vacuous test that can actually pass with the feature broken (or fail with it right) is **high**.
- A branch or loop that runs today but that nothing forces to run is marked **medium (latent)**.
- A misnamed test is high when its name claims coverage it lacks, and low when only a doc comment is wrong.

Sections 1 and 2 are this audit's line-by-line read. Section 3 holds the audio-thread files (live.rs, level.rs, explain.rs). Section 4 is category 9 (level) against the browser specs. Section 5 has the per-file summary.

### 3. Worker-protocol level: does it exist, could it

**Exists only in part.** `apps/web/tests/worker-lanes.test.mjs` and
`worker-perform-replies.test.mjs` lift functions out of `worker.js`'s source
(`lift(name)`) and run them against a stub engine; nothing runs `worker.js`'s
message handler against the real wasm.

**Loading the pkg under Node is solved.** `crates/auracle-wasm/examples/pick_belief.mjs:24-25`
(`const mod = await import(\`${pkg}auracle_wasm.js\`); mod.initSync({ module: readFileSync(\`${pkg}auracle_wasm_bg.wasm\`) });`)
and `tests/web/boot_agrees.spec.js:68-69` do it with no page (3.7 s on CI).

**worker.js is loadable.** It is a module worker (`main.js:209`
`new Worker(\`./worker.js?v=${BUILD}\`, { type: "module" })`) with no static
imports. It touches: `self.location.href` (line 10), `self.postMessage`
(16), `self.onmessage` (2590), `self.addEventListener("unhandledrejection")`
(1160), `indexedDB` behind `if (!self.indexedDB || !faceNs) return null;`
(1214), `fetch` of `perform-wirings.json` (1969), `setTimeout`/`performance`.
`init` imports `./pkg/auracle_wasm.js?v=…` and calls
`mod.default({ module_or_path: m.module || new URL(…) })` (2750-2753), so an
`init` message carrying a compiled `WebAssembly.Module` needs no fetch of the
binary. The farm arrives as `MessagePort`s from main; an `init` with none runs
the walks serially (what `?farm=0` specs exercise).

**Harness (about 100 lines, feasible):** in Node, set `globalThis.self =
globalThis`, `self.location = { href: pathToFileURL("apps/web/worker.js").href + "?v=t" }`,
`self.postMessage = (m) => replies.push(m)`, a no-op `addEventListener`, and a
`fetch` shim for `file:` URLs (Node's `fetch` refuses them); `await
import("apps/web/worker.js")`; post `{ type: "init", seed, poolSize, module:
new WebAssembly.Module(readFileSync("apps/web/pkg/auracle_wasm_bg.wasm")) }`
to `self.onmessage`; then send typed messages and await typed replies. It
needs `make wasm` first, like `boot_agrees.spec.js`, and could run in the
same place (a Playwright test with no page, or `node --test` gated on the pkg
existing). Real farm workers (farm.js over `worker_threads`) are not needed
for message semantics and would be a second step.

**Would move to it:** `bank_kept.spec.js:25` (42.0 s), `patch_guess.spec.js:141`
(38.1 s), `patch_guess.spec.js:224` (50.1 s), `bank_lineage.spec.js:471`
(45.0 s, once the Rust gap above is filled), whole; and the reply halves of
`bank_lineage.spec.js:543` (`pinned.retiring`), `bank_lineage.spec.js:657`
(`refine_progress.seeds`, each `refine_child.seed`), `patch_guess.spec.js:127`
(`{ reason: "no_taste" }`, no `farm_want`), `evolve_breeds_beside_you.spec.js:108`
and `:244` (absorption order, `refined.stopped`, nothing after a stop), and
`evolve_feedback.spec.js:153` (every vote reply carries ratings).

## 6. Patterns worth a helper, a lint or a rule

1. **Inputs sized to a census, not to the claim.**
   - All 62 presets are inserted where `pool_size + 1` turns the pool over (lib.rs:238, :2367, :2552).
   - `preset_standardizer` renders all 62 in seven perform tests.
   - The tempo, arp and lesson tests in §3 do the same.
   - Rule for `crates/AGENTS.md`: *"Size a test's input to its claim: N + 1 inserts turn over a pool of N; the preset bank is a census, not a fixture; a standardizer whose units the assertion does not read is fitted on a handful of presets."*
2. **Restores re-render the bank.** Add a `reload(&Engine) -> Engine` test helper that shares the memo, for every test whose subject is not re-measurement (five tests).
3. **Binding tests that build twins to re-prove engine facts.** This covers `a_stepped_offer…`, `belief_is…`, `farm_walks_breed…` and `evolve_from_this…`; the last two are in the slow tier.
   - Rule for `crates/auracle-wasm/AGENTS.md`: *"A binding test asserts what the binding adds (shape, field names, refusals, ids, key order, buffers, handles) and compares its reply to the engine call once; the engine fact has its test in auracle-session."*
   - The pick-between-steps case has no session test yet, so it moves rather than goes.
4. **Asserts that may not run.**
   - `if reply.get("reason").is_none() { assert… }` (lib.rs:5325, :5334), `if …memo().get_audio(&key).is_none() { assert… }` (lib.rs:5597), `zip` over a possibly empty `phi_std` (lib.rs:424), and the `if` click checks in live.rs.
   - The repo already has the right idiom: `assert!(compared > 0, "…nothing was compared")`.
   - Make that a rule. A grep lint for an `assert!` that opens an `if` block inside a `#[test]` would catch most cases.
5. **Doc comments that describe another test, or more than is asserted.** In session: lib.rs:268, perform.rs:1906, lib.rs:3746 and lib.rs:882; live.rs has six more. Test docs are descriptions too (ADR-004). The `reviewer` agent could check that each claim in a test's doc maps to an assert.
6. **A stale slow list.** `SLOW_TESTS` was measured at PR #65. A fast-tier test that later crosses a minute stays in the gate unnoticed (91 s here). The fast tier could warn or fail on nextest's own `SLOW [> 60s]` mark (a `slow-timeout` with `terminate-after` in a CI nextest profile), so the list is re-checked on every run.
7. **Copied fixtures.**
   - own.rs copies lib.rs's `ground_truth` and `taught`.
   - guess has its own `filled` and `warm`.
   - The wasm tests build serial twins although `twins()` exists, and parse `ranked()[0]["id"]` about 15 times although `pool_ids()` exists.
   - A `#[cfg(test)] pub(crate) mod testkit` in session, plus using the existing wasm helpers, would remove them.
