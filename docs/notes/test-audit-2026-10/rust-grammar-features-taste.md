# Test-quality audit: Rust tests of auracle-grammar, auracle-features, auracle-taste

Main checkout at `42bd322`. Read-only. 215 `#[test]` functions: grammar 120, features 70, taste 25. None of the three crates has a `tests/` directory: every test is a `#[cfg(test)]` module in `src/`.

Timing: one `cargo nextest run -p auracle-grammar -p auracle-features -p auracle-taste --cargo-profile test-fast --test-threads 4` run on the 16-core M3 Max while the machine had other load. Sums of per-test wall time: grammar 6.3 s, features 55.4 s, taste 12.2 s (74 test-seconds; 20 s wall). None of these tests is in the Makefile's `SEARCH_FLOOR` or `SLOW_TESTS` (those are all session-crate tests). CI runners render about 6 to 8 times slower than this machine (testing.md § Rules).

The "on the fixture" column of the rubric does not apply to Rust tests and is omitted.

Paths below are relative to `crates/`.

## Addendum B: the recording mask's margins

`the_mask_is_what_survives_a_recording` (file.rs:571) is a cliff by design: a coordinate is believed on a file when r ≥ 0.9 and rmse ≤ 0.5 on every recording stimulus, and the test fails until `FILE_MASKED` agrees (crates/auracle-features/AGENTS.md, rule 5). `cargo run -p auracle-features --example file_phi` over all 62 presets (the test uses every other one) agrees with the mask on every coordinate today. The believed coordinates closest to the line are `bass_fraction` (r 0.93, rmse 0.43 on the drone and stabs stimuli) and `zcr_mean` (r 0.95, rmse 0.41). The masked one closest to passing is `centroid_std` (fails only on the drone: r 0.84, rmse 0.93). So a preset added to the bank can move `bass_fraction` across the line and force a mask change. That is the contract working, not a flake, and no row is filed. If it starts to churn, a hysteresis band (believe at r ≥ 0.92, mask at r < 0.88, either verdict accepted in between) would stop a borderline coordinate from flipping the mask on every bank edit.
