# Auracle stack audit — September 2026

**Date:** 2026-09-05 · **Scope:** the whole stack as auracle ships it — `auracle` (workspace `bb0c7f5`, 0.2.0) and the three crates it pins from crates.io: `quiver-dsp 0.2.0` (repo HEAD `d3d6488`, 0.3.3), `fugue-evo 0.3.1` (repo HEAD `6b759a2`), `fugue-ppl 0.2.2` (repo HEAD `b8b197c`).

**Method.** Six parallel reviewers, one per layer (auracle-grammar; auracle-features + auracle-taste; auracle-session + auracle-wasm + apps/web; fugue post-remediation; fugue-evo inference layer; quiver post-remediation), reading code against the *pinned* registry sources, not the docs. The three lower repos carry remediated July-2026 audits (`fugue/AUDIT-2026-07.md`, `fugue-evo/AUDIT-2026-07.md`, `quiver/AUDIT.md`); those findings were not re-reported, and reviewers were told to look at what changed since remediation and at the seams auracle actually uses. Auracle itself had never been audited. Every finding below carries a verification status:

- **confirmed (run)** — reproduced in this session by executing code;
- **confirmed** — established by reading the decisive lines (quoted or cited), or by a Python re-implementation of the exact arithmetic;
- **likely / suspected** — mechanism confirmed, magnitude or reachability not measured.

## Executive summary

**The stack is in good shape, and the lower layers are better than most 0.x crates.** All four repos are green under their own gates. The July remediations were spot-checked in HEAD and are still correct (fugue FG-01/02/03; fugue-evo EV-01/05; quiver R5 coefficient folding and R6 output masking are bit-exact by construction). The layering is real: every density in fugue-evo and auracle comes from replaying a program, β is applied exactly once, and RJMCMC bookkeeping for structure-changing moves is right for scored traces. Auracle's own engineering — indexed draw stream, standardizer/posterior coupling, by-name raw-φ log, BS.1770 loudness (coefficients reproduce the published 48 kHz values to 1e-14; a 997 Hz −20 dBFS sine measures −23.055 LUFS) — holds up.

**Where it breaks, the pattern is the same as in July: the primitives are right and the seams are wrong.** The confirmed defects concentrate where one layer's contract meets another's:

1. **Auracle's closed knob domain `[0,1]` meets fugue's half-open `Uniform` `[0,1)`** (AU-G1, confirmed by running). A knob dragged to the stop, two of the 61 shipped presets, the default Vibrato insert, and any hand edit past depth 6 (AU-G2) all score log-prior −∞ under the grammar prior, so `EvolutionChain::init_from` returns `None` and ⚡ evolve silently does nothing. The grammar docs gave `Silence` non-zero weight precisely so no hand edit could make a patch un-evolvable; these do.
2. **A φ coordinate declared unit-bounded is not** (AU-F1, confirmed): `mod_depth_mean` is 2, 3, … for exactly the shaped modulation chains it exists to measure; the load-time repair pass clamps every such vote to 1.0, and a debug build panics on it.
3. **The persistence layer has no quarantine** (AU-S1, confirmed): a save the current build cannot parse is treated as "nothing to restore" and overwritten by the first autosave ~2.5 s after the first vote. There is one IndexedDB key, no schema version on it, and no `worker.onerror` (AU-S2), so a wasm trap leaves the UI in permanent "thinking" with edits deadlocked.
4. **A fugue kernel-selection heuristic is not π-invariant for bounded priors containing negatives** (FG-N1, confirmed by two independent reviewers with simulation). Auracle is *not* exposed today (its only bounded site is `Uniform(0,1)`, where the log-space walk is valid) but fugue-evo's `UniformBoxPrior` with symmetric bounds inside (−1, 0) is, and so is any future auracle site with such a prior.
5. **quiver's randomness is one thread-global stream** (Q-N2, confirmed). Auracle's `(term, spec) → bit-identical samples` contract holds only because it reseeds per render and no module it compiles draws in its constructor — and it seeds *after* compiling the main voice (AU-F4), so that is luck, not construction.

Nothing here is a crash in normal use, and nothing corrupts audio. Everything in the top tier is a silent wrong answer or silent data loss, which is the failure mode this stack's own audits already named as the one to fear.

**Counts.** 43 findings: 8 high, 19 medium, 16 low. Distribution: auracle 24, fugue 9, fugue-evo 5 (plus 3 shared with fugue), quiver 8. Nothing critical: the two candidates (AU-G1 and AU-S1) each need a user action that is common but not universal.

## Cross-stack findings

### X-1 — Version skew and a stale "tracked upstream" note (low, confirmed)

Auracle pins `quiver-dsp = "0.2.0"`; the repo is at 0.3.3. `diff -r` of the two `src/` trees touches five files with no API removals: `voct_to_hz` gained a ±32-octave clamp (0.3.0, commit `1758971`), `DelayLine` gained `with_max_delay`/`with_unclamped_feedback`/`with_linear_time`/`tape` and the registry gained `"tape_delay"`, and the wasm engine gained an audio-input path and `set_param_by_name`. `www/reference/src/design/open-questions.md` and `safety.md` still say the clamp is "open upstream, non-blocking"; it shipped a month ago. Upgrading is safe for every module the grammar compiles (all 50 module/port names were checked against both versions), and renders inside ±32 octaves are unchanged, so no `RENDER_EPOCH` bump is needed — but for pathological CV the two versions render *differently* (0.2.0: `inf` increment → phase reset; 0.3.x: finite ~THz aliasing), so the upgrade is not a pure no-op for an MH search that can reach such values through chained `Offset`s. Fix: bump, update the two doc pages, and decide deliberately whether that behavioural change wants an epoch bump.

### X-2 — No MSRV in fugue-evo or auracle; every repo floats on `stable` with `-D warnings` (low, confirmed)

`fugue` declares `rust-version = "1.87"` and checks it in CI; `quiver` declares 1.78; `fugue-evo` and `auracle` declare nothing (`cargo info fugue-evo` → `rust-version: unknown`). All four CI configurations use `dtolnay/rust-toolchain@stable` with clippy as errors, so a new stable release can turn every repo red at once through a new lint, unrelated to any change. Fix: declare `rust-version` in fugue-evo (≥1.87, inherited from fugue) and auracle; consider pinning the CI toolchain and bumping deliberately.

### X-3 — auracle's config of fugue-evo is never built by fugue-evo's CI (medium, confirmed)

fugue-evo's CI runs everything `--all-features`; nothing builds `--no-default-features --features std,ppl` (auracle's exact config) or the `std,parallel,checkpoint,classic` config that `CLAUDE.md` calls CI-relevant. It happens to build (verified here: 286 tests green) because no ungated reference from always-compiled modules into `classic` exists today, but nothing guards it. Also: `nalgebra`, `rand_chacha`, `serde_json` are unconditional dependencies used only by `classic` code, so auracle's wasm bundle pays their compile time and code size for nothing. Fix: two matrix jobs (native + wasm32 for `std,ppl`); gate the three dependencies behind `classic`.

### X-4 — Native and wasm renders are not bit-identical, and nothing tests that they are (low, likely)

quiver routes every DSP transcendental through `libm` (verified by grep: std float methods appear only in tests, `visual.rs`, `mdk.rs`, MIDI helpers), so its part of the contract is plausible. But auracle-features' FFT uses `rustfft`'s runtime planner (AVX → SSE → wasm-SIMD → scalar by CPU detection), fugue uses std `ln/exp/sqrt/cos` in its proposals, and quiver's own golden-vector gate runs on x86-64 Linux only. The persistent render cache's "a hit is indistinguishable from a miss" claim is therefore per-platform. Fix: state the contract as per-platform, or use `FftPlannerScalar` and add a wasm execution of the golden vectors.

### X-5 — `EvolutionChain::step` is fed an unscored trace only via `init_from`, and that is the one path auracle uses — good; but the same API has two sharp edges auracle should know (medium, confirmed)

(a) `step()` silently ignores `override_site` (only `run_chain` honours it), so `Reflect` bounds cannot be applied through the incremental API auracle uses. (b) `step()` re-scores `current` every call: two full program executions (two fitness evaluations) per transition unless the fitness is memoised — auracle does memoise (`SurrogateFitness.memo`), which is why this is medium not high. (c) A trace built by `trace_of`/`to_trace` and passed *directly* to `step()` (bypassing `init_from`) over-accepts structure-shrinking moves until the first acceptance, because the death term reads the caller's stored per-choice `logp` (zero in every `to_trace`). Auracle does not do this today. Fix (fugue-evo): `step` should take overrides and carry the cached log-weight; document "`current` must come from `init`/`init_from`/`step`".

## auracle

### auracle-grammar

**AU-G1 — Any continuous site at exactly `1.0` gives the term log-prior −∞; the patch is silently un-evolvable** · **high · confirmed (run)**

`prior.rs` `u01()` is `Uniform::new(0.0, 1.0)`; fugue's `Uniform::log_prob` (`fugue-ppl-0.2.2/src/core/distribution.rs:320`) returns `−∞` for `x >= high`. Auracle's own domain contract treats `1.0` as legal everywhere: `genome.rs:1716` `PARAM_DOMAIN = 0.0..=1.0`, `in_domain`, `clamp_domains` (clamps *to* 1.0), `edit.rs:100` `v.clamp(0.0, 1.0)`, and the web knob `Math.min(1, …)` (`main.js:9210`). Producers of exactly 1.0 today: a knob dragged to the stop; `mutate.rs:506` `default_node(Vibrato)` (`mix: 1.0`); `presets.rs:1055` "Sea Change" (`mix: 1.0`) and `:1995` "Ask The Dice" (`mod_depth: 1.0`); any tree repaired by `clamp_domains` from a value > 1.

Reproduced here by scoring under `PatchGrammarPrior::default().model()` with `ScoreGivenTrace`:

```
presets with -inf prior: 2/61   ("Sea Change", "Ask The Dice")
[First Bass] knob amp#attack = 1.0:   in_domain=true  log_prior=-inf
[First Bass] knob amp#attack = 0.999:                 log_prior=-10.85
insert Vibrato (default node):                        log_prior=-inf
```

Consequence chain (`auracle-session/src/engine.rs:1950`): `refine_one` → `chain.init_from(seed)` → `total_log_weight()` non-finite → `None` → `refine_seed` returns `None`, indistinguishable from "the walk did not move". ⚡ evolve on such a patch does nothing and says nothing. Fix: make the domain half-open where it is enforced (`set_param`, `clamp_domains`, `ParamMap::clamp_input`, `in_domain`: `0.0 <= v < 1.0`, clamp to `1.0 − f64::EPSILON`), fix the three literal `1.0`s, and make `refine_seed` distinguish "seed outside prior support" from "no move". Add a test that every preset, every `default_node`, and every `apply_struct_op` result has a finite prior.

**AU-G2 — Hand-edit ceilings (`MAX_DEPTH = 9`, `MAX_MOD_DEPTH = 4`) exceed the prior's support (`max_depth = 5`, `max_mod_depth = 2`)** · **high · confirmed (run)**

`prior.rs:500` forces `#leaf` with `Bernoulli(1.0)` at `depth >= max_depth`, and `mod_weights_at` zeroes `Op`/`Pair` at `depth >= max_mod_depth`; the deepest audio term with positive mass has `depth() == 6`, the deepest mod term `3`. `mutate.rs:1400-1404` accepts audio depth ≤ 9 and mod depth ≤ 4 — the comment there says the ceiling "is there to protect the realtime voice rather than to shape the search", without noting that the prior gives such trees zero mass. Reproduced: inserting `Delay` at the root of "First Bass" repeatedly, `validate_tree` OK at every step, `log_prior` finite through depth 6 (−25.5) and `−∞` at depth 7 and 8. Same silent `init_from → None` path as AU-G1. Fix: derive the ceilings from the prior (`max_depth + 1`, `max_mod_depth + 1`) or raise the prior's bounds to the ceilings.

**AU-G3 — The "taste tilt" reshapes the target, not the proposal; the reference claims the opposite** · **medium · confirmed**

`engine.rs:1948` installs `self.biased_prior()` (reweighted `source_weights`/`op_weights`/`mod_weights`) as the *prior* of `EvolutionModel`; fugue-evo's `target_model()` is `prior.model() + factor(β·f)`, and fugue's usize proposal is `PriorResample` from that same categorical, so the Hastings terms cancel and the chain targets π' ∝ p_tilted(x)·exp(β·u(x)). MH is valid (a proper target, and the seed is scored under the same tilted prior), but `www/reference/src/search/proposals.md:121-124` says "tilting the proposal changes the kernel, not the target … the stationary distribution is unchanged", which is false; the parsimony mass the walk climbs and the `RefineKeep::Best` ranking are both under the tilted prior. Fix: document it as a prior tilt (and rename), or implement a true proposal tilt via a custom site proposal with the Hastings correction (needs a fugue hook: 0.2.2 offers only `PriorResample` for usize).

**AU-G4 — `ReplaceTree`/`InsertTree` do not normalise modulation fragments** · **medium · likely**

`SetModTree` calls `.normalized()`; the two tree-graft ops do not. A fragment with `Op { input: None }` or `Pair { a: None }` encodes `#mod=0` where the prior weight is zero → −∞ (as above); a one-parameter `Op` with `p1 ≠ 0` is not encoded, so `from_trace(to_trace(t)) ≠ t` and `refine_one`'s "did it move" test is fooled. Fix: walk the fragment's mod slots with `normalized()` in `finish()`.

**AU-G5 — `sample_with_rng` disagrees with `model()`: it can never draw `Silence` and gives its mass to `Formant`** · **medium · confirmed (run)**

`prior.rs` `sample_audio` has `_ => Formant` catching source index 5 and 6. Measured over 20 000 seeded draws: `sample_with_rng` produced 0 `silence` terms, `model()` produced 141. The two samplers are documented as agreeing; `EvolutionaryGenome::generate` and several tests use the RNG path. Fix: `5 => Formant, _ => Silence`, plus a kind-frequency agreement test.

**AU-G6 — `diff.rs` label tables are stale for exactly the newest productions** · **low · confirmed** — `"src"` lacks `silence`; `"op"` lacks `shift, comp, duck, gate, vocoder`; `"mod"` lacks `euclid, op, pair`. The comment already says "they fell out of date once". Derive from one shared table and assert lengths against `N_SOURCES`/`N_OPS`/`N_MODS`.

**AU-G7 — Legacy-trace default for `mdepth` (0.3) disagrees with the serde default (0.0)** · **low · confirmed** — the same v1 save decodes to two different terms depending on route; breaks dedup/`distance()` assumptions. Use 0.0 in the decoder.

**AU-G8 — Mod cables that compile to nothing leave advertised knobs without live handles** · **low · confirmed** — `Follow` under a source returns `Ok(None)` from `build_mod`, so `wire_mod` registers no `mdepth` handle while `describe.rs` still lists it; a live-param miss falls back to a full patch swap (audible). Also a grammar-level dead production: `Follow` under a source has positive prior mass and is inaudible by construction. Extend `every_advertised_live_site_has_a_live_handle` to all knobs.

**AU-G9 — `from_trace` accepts out-of-range categorical indices without error** · **low · suspected** — `octave: get_usize(..)? as i8 - 2` unchecked; enum decoders wrap with `% len`. Unreachable from MH or `set_param`; reachable from a hand-made trace. Cheap `InvalidStructure`.

Non-findings worth recording: all 50 module/port names in `compile.rs` match quiver-dsp 0.2.0 (and 0.3.3); the codec writes exactly the sites `model()` samples for every production and addresses are injective; log-prior is counted once; lock rejection is checked in both directions (exact Metropolis-within-Gibbs); recursion depth is bounded at every wasm entry by `validate_tree` or the prior — except `import_patch` (AU-S3).

### auracle-features

**AU-F1 — `mod_depth_mean` is declared unit-bounded but is ≥ 1, and 2, 3, … for shaped chains; the load-time repair clamps it** · **high · confirmed**

`structural.rs:524-533` lists `mod_depth_mean` in `UNIT_NAMES`; `:683-687` computes `depth_sum / filled` where `ModNode::depth()` (`term.rs:1329-1340`) is 1 for a bare modulator and `1 + input.depth()` for `Op`. `migrate.rs:257-275, 334-372` (`repair_log`, called at every load) clamps any `UNIT_NAMES` cell outside `[0,1]` and counts it as repaired. So every stored vote on a patch with an `Op`- or `Pair`-shaped modulator is rewritten to "unshaped" on the next load, while freshly featurised pool rows keep 2.0 — the standardizer is fit on a mixture. In a debug build (`cargo test` without `--profile test-fast`) the `debug_assert!` at `:726` panics on ~4 % of prior draws. Fix: remove it from `UNIT_NAMES` (it is a count-like mean) or redefine it bounded (`1 − 1/depth`); test a shaped chain; bump `RENDER_EPOCH` if the definition changes.

**AU-F2 — Frame silence is recognised only at exactly zero power** · **medium · likely** — `audio.rs:312` `if power > 1e-12` on unnormalised windowed FFT power trips at amplitude ≈ 2e-9 (−173 dBFS). Rests are zero only because quiver's `Adsr` snaps exactly to 0 at `EXP_DONE` and the VCA is multiplicative; a release or chord tail that outlasts the 0.15–0.2 s rest never gets a chain break, and the #51 flux fix and the segment features depend on it. Fix: define silence relative to the phrase (e.g. −60 dB of global RMS).

**AU-F3 — The cache namespace does not cover the quiver version or `AUR_DCB_ALWAYS`** · **medium · confirmed** — `cache.rs:103` (`RENDER_EPOCH` doc lists formula/vet/compiler changes, not the DSP dependency); `compile.rs:2876` `std::env::var("AUR_DCB_ALWAYS")` inserts an extra `Svf` into the voice tail, so a process with it set writes different φ into the same persistent namespace. Fix: fold quiver's version into `cache_namespace`; make the DC-blocker choice part of `PhraseSpec`.

**AU-F4 — The render seeds quiver's RNG after compiling the main voice** · **medium · confirmed (latent)** — `render.rs:75` `compile(...)` then `:81` `quiver::rng::seed(spec.seed)`; chord voices compile after the seed. Deterministic today only because no module the grammar compiles draws in its constructor (quiver's `analog.rs` constructors do; see Q-N2). Move the seed above `compile`. Zero cost.

**AU-F5 — Stars likelihood applies the imputation attenuation to `u`, not to `(c_k − u)`** · **medium · confirmed** — `model.rs:383` `u = utility_mix(x) * attenuate(...)`, then `sigmoid(cuts[k] − u)`; keep/kill at `:376` correctly attenuates the difference. At `u = 0` the code applies no correction at all; at `u = 1.5` it moves the probability away from the Monte-Carlo truth (0.205 vs 0.133). Only reachable for `Stars` rows with imputed coordinates, i.e. after a stimulus-tag bump — exactly when #55 says it matters. Fix: `sigmoid(a·(cuts[k] − u))` on both bounds. (Filed under features/taste jointly because the fix spans both crates' tests.)

**AU-F6 — φ is not bit-identical across CPUs** · **low · confirmed (mechanism)** — see X-4.

**AU-F7 — `rms_mean`/`rms_std` are measured after the peak-cap gain** · **low · confirmed** — the ~15 % of patches pulled down by the ceiling read as "quiet"; `crest` already carries peakiness. Measure at the loudness target or document the confound.

**AU-F8 — `tail_ratio` measures amp-envelope release, not effect tails** · **low · confirmed** — the amp ADSR→VCA is the last stage after every effect (`compile.rs:1547-1586`), so a reverb tail is multiplied by the release; the doc overstates it.

### auracle-taste

**AU-T1 — Style labels are not aligned across fits; persisted `style_names` can attach to a different lens after every refit** · **medium · confirmed** — `model.rs:850-900` `aligned()` aligns *within* one posterior to its own last draw; `engine.rs:1601` replaces `self.posterior` with no reference to the previous one; names are keyed by index (`:1918-1927`) and `K` grows with the log (`:1582`). With probability ≈ 1 − 1/K! two consecutive fits order the lenses differently. Fix: `aligned_to(&previous_theta_means)` in `fit_posterior`; map names by best match when `K` grows.

**AU-T2 — Miscellaneous robustness edges** · **low · confirmed** — `TastePosterior` loaded with `n_features ≠ d` silently truncates in `dot` (`model.rs:308`); `FitSet::build` indexes the standardizer without a dimension check (`observe.rs:463`, panic on mismatch); `reweighted` (`model.rs:790+`) ignores `absent`, inconsistent with `fit`; stars log-prob `(upper − lower).max(1e-12).ln()` floors at −27.6 by cancellation; stale numbers in docs (`d = 40`, "37 doubles", 206 sites — φ is 41 today) and a test that hard-codes 40.

**AU-T3 — Serialization: non-finite floats become `null`** · **low · confirmed** — `serde_json` writes NaN/inf as `null`; observation rows are then dropped by `tolerant_observations` on reload (a writer-side source for exactly the "one `null` in one φ vector" the doc describes); `Standardizer` has no tolerant path, so a `std = inf` would fail the profile load. Assert finiteness at write.

### auracle-session, auracle-wasm, apps/web

**AU-S1 — A save the current build cannot parse is silently overwritten by a fresh session** · **high · confirmed**

`auracle-wasm/src/lib.rs:433-446` `import_session_deferred` returns `"[]"` when `serde_json::from_str::<SessionState>` fails (and `import_session` returns 0); `worker.js:463-476` treats zero jobs as "nothing to restore" and boots from the prior; `main.js:830-832` `case "saved": idbPut("state", …)` is unconditional and is scheduled ~2.5 s after any `status`/`fitted`/`refined`. One IDB key, no schema version on the record (admitted at `engine.rs:715-718`), no backup. Trigger: an older cached build opening a newer save, a new enum variant, or one corrupt bank tree — `SessionState` deserialisation is all-or-nothing except the observation rows. `lib.rs:2030-2049` records this having happened once; the fix chosen (`#[serde(default)]`) cannot cover unknown variants or future fields. Fix: tri-state result from `import_session*` → `restore_failed`; on failure copy the record to `state-quarantine-<ts>` before any write and disable autosave until acknowledged; version the record and keep a two-slot ring (`state`, `state-prev`).

**AU-S2 — No `worker.onerror`; a wasm trap leaves a poisoned engine and a UI that never learns** · **high · confirmed**

`main.js:704` only sets `worker.onmessage`; `worker.js` wraps only `init` and `render` in try/catch. With `panic = "abort"` a panic traps and wasm-bindgen's `&mut self` borrow flag is never cleared ("recursive use of an object" thereafter). `fitting` is reset only in `case "fitted"`, the evolve button only in `case "refined"`, `editInFlight` only by a `bench`/`edit_rejected` reply — the deadlock CONTRIBUTING names. The `role="alert"` for a crashed engine that the README promises exists only for the worklet and `boot_failed`. Fix: `worker.onerror` + `messageerror` → alarm, reset per-request state, stop autosave; wrap the worker `switch` in try/catch and post `engine_error`; consider rebuilding `WasmEngine` from the last `saved` JSON.

**AU-S3 — `import_patch` skips the size/depth ceilings every other write route enforces** · **high · confirmed (bypass); suspected (overflow)** — `lib.rs:1012-1028` does `clamp_domains()` then `commit_edit(None, tree, Untold)`, no `validate_tree`; `compile` has no depth guard of its own, and `Origin::Edited` "always lands" (`engine.rs:2081-2085`). A shared file with a depth-40 tree enters the pool, evicts a member, and its out-of-range φ enters the log on the next vote; at ~60 nested nodes the by-value recursive compiler (38 KB+ frames, `Makefile:8-15`) is in stack-overflow territory on the 8 MB wasm stack, which is the trap in AU-S2. The same JSON goes to `LivePoly::set_patch` on the audio thread. Fix: `validate_tree` in `import_patch`; a depth check inside `compile` so no caller can bypass it.

**AU-S4 — Votes on an evicted id are dropped silently while the UI records them as taken** · **medium · confirmed** — `lib.rs:667-688` `record_duel/keep/stars` no-op when `find()` fails; `worker.js:952-975` posts `status` regardless; `main.js:975-990` increments the Brier tally and saves; `rateRow` toasts "rated ★". Reachable in the 7 s undo window (`UNDO_WINDOW_MS`) if evolve/preset-load/import evicts a duel side. Fix: return `bool`; toast and roll back.

**AU-S5 — Patch swaps compile on the audio render thread** · **medium · confirmed** — `live.rs:1043-1055` runs `build_voice` (full `compile`) inside `process()` for 4 quanta; `:432-436` parses the whole tree JSON in the worklet's `onmessage`, also on the render thread. The docstring's "a dropped quantum of silence is inaudible" holds for this node only: duel auditions, master gain, analysers and the recorder share the render thread. Also per-quantum allocation in `tick_arp` (`held.clone()`), `set_param` (`addr.to_string()`), and a `HashMap<String>` lookup per voice per smoother — CONTRIBUTING's "allocation-free per quantum" is aspirational for those paths. Fix: compile in the worker and transfer a ready voice, or at least parse off-thread and pre-size buffers.

**AU-S6 — Unbounded growth in engine history and main-thread audio caches** · **medium · confirmed** — `lineage`, `events` (two raw-φ vectors per edit/revert/play flush), `forecasts`, `style_shares`, `shown_pairs`/`shown_candidates` grow forever and are serialised into every autosave; `renders` (`main.js:41`) holds one ~0.6 MB `AudioBuffer` per id ever auditioned, never pruned. Cap or spill `events`; prune on eviction (`applyViews` already computes `evicted`).

**AU-S7 — Every reload opens a new τ session; site count grows with reload count** · **medium · confirmed** — all three import paths call `begin_session`; sites = `d·K + n_sessions + 5`. A once-per-visit voter accumulates a nuisance site per visit forever, each stealing single-site MH budget. Merge short sessions, or start a new one only after N observations or a wall-clock gap.

## quiver (`quiver-dsp` 0.2.0 pinned; HEAD 0.3.3)

Verified solid: R5 coefficient folding is bit-exact (`x·1.0 == x`, `+0.0` cannot flip a `+0.0`-initialised sum); R6 masking keeps every stateful update unconditional (`Vco`, `Lfo`, `NoiseGenerator` all checked; `output_masking.rs` pins it bit-for-bit); no `HashMap` iteration in compile or tick order; all DSP transcendentals go through `libm`; `Svf` bounded (`k ≥ 1e-5`, `fc ≤ 0.49 fs`, soft-clipped states); `Granular` owns a seeded RNG with a fixed pool; `PolyPatch::tick` allocation-free; `write_wav` correct; `voct_to_hz` clamp exact within ±32 octaves.

**Q-N1 — `KarplusStrong`'s stretch stage is unstable for positive `stretch` at most pitches; blow-up leaves the module permanently silent** · **high · confirmed (simulation)** — `oscillators.rs:655-672`: as a one-pole, `y[n] = L(1+s)c·x + L[(1+s)(1−c) − s]·y[n−1]`; for `s = 0.5, c = 0.99` the section's Nyquist gain is 2.88, and whether the whole loop exceeds unity depends on the fractional part of the period (i.e. pitch). Python re-implementation sweeping `stretch ∈ {0.25..1}`, `damping ∈ {0.5..1}`, `voct ∈ [−3, 4]`: growth to `inf` within 2 s at many combinations; C4 and +4 octaves happen to be stable (`frac ≈ 0.5`), which is why tests at C4 never see it. Once `leaked` is `inf`, `excite()` refills only `buffer`, never `last_output`, so the module is silent until `reset()`. `stretch` is `CvBipolar` clamped to ±1, so any ±5 V CV saturates at `s = 0.5`. **Auracle is not exposed**: `compile.rs:1820` pins `stretch` to a constant 0.0. Fix: a true first-order allpass for the stretch stage; reset `last_output` in `excite()`; finite guard; a stretch sweep test at several pitches.

**Q-N2 — Randomness is one thread-global stream seeded from `SystemTime`; the determinism contract holds only under conditions the crate neither documents nor enforces** · **high · confirmed** — `rng.rs:14-19, 85-102`: `thread_local!` seeded from wall clock on first touch under std, a fixed constant under wasm32 (so native and wasm disagree by default); `rng::seed` reseeds the calling thread only. `NoiseGenerator` (2 draws/tick), `PinkNoiseState`, `KarplusStrong::excite` (`period` draws), `BernoulliGate`, and `AnalogVco` (one per tick **and four at construction**) all share it, so patch B's noise depends on what patch A consumed and on how many analog modules were constructed. `Patch::reset()` does not reseed (`mdk_harness.rs:37` allowlists `noise/reset_clears_state` for this reason); the golden `noise` test passes only because it seeds first. Only `Granular` owns its RNG — the right design, applied to one module. Fix: per-module owned `Rng`, `GraphModule::seed` (default no-op), `Patch::seed(u64)` deriving per-node seeds, `reset()` re-deriving. Auracle workaround today: seed before constructing modules (AU-F4), never share a thread, avoid `AnalogVco`.

**Q-N3 — `set_param_by_id` (and 0.3.x wasm `set_param_by_name`) recompiles the whole graph on the audio thread and zeroes routing buffers** · **medium · confirmed** — `graph.rs:1806-1827 → 1168-1172 → 1556-1557`: `invalidate()` drops `Routing`, next `tick()` runs `compile()` (two `HashMap`s, several `Vec`s); the npm worklet calls it directly from `process()`. `out_buf` restarts at 0, so a cycle-breaker gets one sample of silence in its feedback path. **Q-N4 — Cycle-breaker scheduling depends on node insertion order, not topology** · **medium · confirmed** — `graph.rs:1466-1475`: *every* edge into a breaker is dropped, not just back-edges, so an acyclic `vco → delay → out` gets a one-sample delay-path latency unless the VCO was `add()`ed first; the golden `delay_chorus` patch has the delay reading the VCO's previous sample with no cycle present. Deterministic for a fixed construction order (auracle's is), but "patch" in the contract silently includes insertion order. Fix: drop only true back-edges (DFS), rebaseline the golden hashes deliberately.

**Q-N5 — The golden-vector gate is thinner than its header claims** · **medium · confirmed** — five patches, one second each; no input receives more than one cable (the header's "multi-edge inputs" is false — `vca.in` and `vca.cv` are different ports), no actual feedback loop, no `connect_attenuated`, no `PolyPatch`, no `set_param` after compile, no `tick_block == tick` check, `std`-only, x86-64 only. Add those cases; store vectors as data so wasm can compare.

**Q-N6 — "Complete NaN sanitisation" is true only at the graph boundary** · **medium · confirmed** — `PitchShifter`, `Granular` (with `freeze`, a NaN stays forever), `Wavefolder` take unsanitised input; internal blow-ups (Q-N1) are not covered by input sanitisation at all; `nan_recovery.rs` covers five modules; the MDK harness never fires trigger inputs so its stability checks on trigger-driven modules are vacuous (likely). **Q-N7 — wasm observer path aliases and allocates on the audio thread** · **medium · confirmed** — `engine.rs:586-594, 633-658`: one sample captured per `observer_interval` blocks (1 in 1024 at 128-frame quanta) though `collect_sample` per sample exists; `flush_ready` clones scope buffers and `String`s inside `process()`; per-subscription SipHash lookup per sample.
